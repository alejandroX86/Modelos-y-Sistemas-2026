🎯 ¿Qué es un Diagrama de Secuencia?

Un Diagrama de Secuencia es un diagrama de interacción que muestra cómo los objetos interactúan entre sí en una secuencia temporal. Es fundamental en el análisis y diseño de sistemas porque permite visualizar el flujo de mensajes entre los diferentes participantes del sistema.

👤
Línea de Vida (Lifeline)

Representa la participación de un objeto o actor en la interacción. Se muestra como una línea vertical que desciende desde el participante. Indica la existencia del objeto en el tiempo.

⬛
Caja de Activación

Rectángulo delgado y vertical que se superpone a la línea de vida. Indica el período durante el cual el objeto está ejecutando una operación o está activo procesando un mensaje.

➡️
Mensaje Sincrónico

Flecha sólida con punta cerrada. El emisor espera una respuesta antes de continuar. Representa una llamada a método o función que bloquea al emisor hasta completarse.

⇢
Mensaje Asincrónico

Flecha con línea punteada y punta abierta. El emisor no espera respuesta y continúa su ejecución inmediatamente. Usado para eventos o notificaciones.

⬅️
Mensaje de Retorno

Flecha punteada que regresa al emisor original. Indica la respuesta o el valor retornado de una operación. Es implícito en mensajes sincrónicos.

📋
Nota

Rectángulo con esquina doblada que contiene comentarios o restricciones. Proporciona información adicional sobre elementos del diagrama.

🔄
Fragmento Combined

Marco que agrupa mensajes con condiciones especiales: alt (alternativa), opt (opcional), loop (bucle), par (paralelo). Define comportamientos condicionales.

⏱️
Línea de Tiempo

El tiempo fluye de arriba hacia abajo. Los mensajes en la parte superior ocurren antes que los de la parte inferior. La secuencia temporal es fundamental.

📝 Explicación Detallada del Proceso

  1. Inicio de Sesión: El usuario ingresa sus credenciales (nombre de usuario y contraseña) en la interfaz de login. Estos datos son capturados por el formulario.
  2. Validación de Formato: La interfaz realiza validaciones básicas del lado del cliente: verifica que los campos no estén vacíos, que el email tenga formato correcto y que la contraseña cumpla con los requisitos mínimos de seguridad.
  3. Consulta a Base de Datos: El controlador de autenticación consulta la base de datos buscando un usuario que coincida con el nombre de usuario proporcionado. Se utiliza una consulta parametrizada para prevenir inyección SQL.
  4. Verificación de Contraseña: Si se encuentra el usuario, se compara la contraseña ingresada (previamente hasheada con el mismo algoritmo) con el hash almacenado en la base de datos. Nunca se almacenan contraseñas en texto plano.
  5. Generación de Token: Si las credenciales son correctas, se genera un token JWT (JSON Web Token) que contiene información del usuario (ID, rol, permisos) y una fecha de expiración. Este token se firma con una clave secreta.
  6. Registro de Sesión: Se registra el inicio de sesión en la tabla de auditoría, guardando IP, fecha/hora, y dispositivo utilizado. Esto es importante para seguridad y trazabilidad.
  7. Redirección: El token se almacena en el localStorage o cookies del navegador y el usuario es redirigido al dashboard principal del sistema. Todas las peticiones posteriores incluirán este token en el header Authorization.
⚠️ Consideraciones de Seguridad:
  • Uso de HTTPS para encriptar la comunicación
  • Rate limiting para prevenir ataques de fuerza bruta
  • Hash de contraseñas con bcrypt o argon2
  • Token con expiración corta y refresh token
  • Validación de CSRF tokens

📝 Explicación del Proceso de Compra

  1. Agregar al Carrito: El cliente selecciona productos y los agrega al carrito de compras. Cada producto incluye ID, cantidad, precio unitario y opciones seleccionadas (talle, color, etc.). El carrito se mantiene en sesión o localStorage.
  2. Iniciar Checkout: Cuando el cliente decide comprar, hace clic en "Proceder al Pago". El sistema valida que el carrito no esté vacío y que el usuario esté logueado (si es requerido).
  3. Crear Pedido: Se genera un nuevo registro de pedido con estado "Pendiente de Pago". Se calcula el subtotal, impuestos, costo de envío (según ubicación y peso) y total final. Se aplica cualquier descuento o cupón válido.
  4. Verificación de Stock: Antes de procesar el pago, se consulta el sistema de inventario para verificar que todos los productos estén disponibles en la cantidad solicitada. Esto previene ventas de productos sin stock.
  5. Procesamiento de Pago: Se envía la información de pago (tokenizada, nunca el número de tarjeta completo) a la pasarela de pago (MercadoPago, Stripe, etc.). La pasarela valida con el banco emisor de la tarjeta.
  6. Actualización de Stock: Si el pago es aprobado, se decrementa el stock de los productos comprados. Esto se hace en una transacción de base de datos para asegurar consistencia. Si algún producto queda sin stock, se marca como "Agotado".
  7. Confirmación: Se cambia el estado del pedido a "Confirmado", se genera un número de pedido único y se envía un email de confirmación al cliente con el resumen de la compra y el tiempo estimado de entrega.

📝 Explicación del Proceso de Registro

  1. Completar Formulario: El usuario ingresa sus datos personales: nombre, apellido, email, teléfono, DNI, fecha de nacimiento y contraseña. El formulario incluye validación en tiempo real (client-side) para mejorar la experiencia de usuario.
  2. Validación de Formato: Al enviar el formulario, un validador verifica que todos los campos cumplan con los requisitos: email con formato válido (regex), contraseña con mínimo 8 caracteres incluyendo mayúsculas, números y símbolos, teléfono con formato correcto, DNI numérico y sin puntos.
  3. Verificación de Unicidad: Se consulta la base de datos para verificar que el email y el DNI no estén registrados previamente. Esto previene cuentas duplicadas. La consulta es indexada para ser rápida incluso con millones de usuarios.
  4. Encriptación de Contraseña: Antes de guardar, la contraseña se hashea usando bcrypt con un salt único generado aleatoriamente. Nunca se guarda la contraseña en texto plano. El salt se almacena junto al hash para permitir la verificación posterior.
  5. Guardar Usuario: Se inserta el nuevo usuario en la base de datos con estado "Pendiente de Confirmación". Se genera un token único de confirmación (UUID) que se almacena en una tabla separada con fecha de expiración (24 horas).
  6. Email de Confirmación: Se envía un email al usuario con un link de confirmación que incluye el token. El email contiene instrucciones claras y un botón de acción. Si el email no se puede enviar, se registra el error y se reintenta automáticamente.
  7. Confirmación de Cuenta: Cuando el usuario hace clic en el link, se valida el token, se cambia el estado a "Activo" y se redirige al login. El token se invalida inmediatamente después de usar para prevenir reutilización.

📝 Explicación del Sistema de Búsqueda

  1. Entrada de Búsqueda: El usuario ingresa términos de búsqueda en el input y puede aplicar múltiples filtros simultáneos: categoría, rango de precios (min-max), marca, disponibilidad de stock, rating mínimo de clientes, etc. La interfaz permite búsqueda en tiempo real (autocomplete) o búsqueda tradicional con botón.
  2. Procesamiento de Query: El motor de búsqueda recibe los parámetros y construye una consulta optimizada. Limpia el texto de búsqueda (elimina caracteres especiales, normaliza acentos), tokeniza en palabras clave y prepara los filtros para la consulta SQL o Elasticsearch.
  3. Verificación de Caché: Antes de consultar la base de datos, se verifica si existe una consulta idéntica en caché (Redis). Se genera una clave única basada en los parámetros de búsqueda (hash MD5). Si hay cache hit, se retornan los resultados inmediatamente (5-10ms vs 200-500ms de DB).
  4. Consulta a Base de Datos: Si no hay caché, se ejecuta una query compleja que incluye: búsqueda FULLTEXT en nombre y descripción, JOIN con tablas de categorías y marcas, filtrado por rangos de precio y stock, ordenamiento por relevancia/precio/fecha, y paginación (LIMIT/OFFSET). Se usan índices para optimizar.
  5. Almacenamiento en Caché: Los resultados se guardan en Redis con un TTL (Time To Live) de 15 minutos. Esto reduce drásticamente la carga en la base de datos para búsquedas populares. El caché se invalida automáticamente cuando se actualiza un producto.
  6. Presentación de Resultados: Los resultados se muestran con paginación (20 productos por página), destacando los términos buscados, mostrando imagen, precio, rating y disponibilidad. Se incluye el total de resultados y tiempo de búsqueda. Se sugieren búsquedas relacionadas.
⚡ Optimizaciones Implementadas:
  • Índices compuestos en columnas frecuentemente filtradas
  • Caché de consultas frecuentes (Redis/Memcached)
  • Búsqueda full-text indexada (Elasticsearch opcional)
  • Paginación con keyset en lugar de offset para grandes volúmenes
  • Lazy loading de imágenes y datos adicionales

📝 Explicación del Proceso de Pago

  1. Tokenización de Tarjeta: El cliente ingresa los datos de su tarjeta (número, fecha de expiración, CVV). Inmediatamente, estos datos se envían a la pasarela de pago (nunca tocan nuestro servidor) y se recibe un token único que representa la tarjeta. Esto cumple con PCI DSS y elimina el riesgo de almacenar datos sensibles.
  2. Inicio de Transacción: Se envía el token junto con el monto a cobrar, moneda, descripción de la compra y datos del cliente a la API de la pasarela de pago (MercadoPago, Stripe, etc.). Se incluye un ID de transacción único generado por nuestro sistema.
  3. Análisis de Fraude: Antes de procesar el pago, un sistema de detección de fraude analiza la transacción en milisegundos: verifica si la IP es de alto riesgo, si el dispositivo fue usado en transacciones fraudulentas previas, si el monto es inusual para ese usuario, velocidad de intentos, etc. Asigna un score de riesgo (0-100).
  4. Autorización con Banco: Si el score de fraude es aceptable, la pasarela contacta al banco emisor de la tarjeta a través de las redes de pago (Visa/Mastercard). Se envía el token (que el banco puede mapear al número real), monto y datos de la transacción.
  5. Validación de Fondos: El banco verifica: que la tarjeta exista y esté activa, que el CVV sea correcto, que no esté reportada como robada, que tenga fondos disponibles o crédito suficiente, y que no exceda límites de compra. Si todo está OK, reserva el monto (authorization) y devuelve un código de autorización.
  6. Confirmación y Captura: La pasarela notifica a nuestro sistema que el pago fue aprobado. Se genera un comprobante de pago con todos los detalles, se actualiza el estado del pedido a "Pagado", y se envía un email al cliente con el comprobante adjunto. El monto se captura (transfiere realmente) automáticamente o manualmente según configuración.
🔄 Manejo de Errores y Reintentos:
  • Fondos Insuficientes: Se notifica al cliente inmediatamente sugiriendo otro medio de pago
  • Timeout del Banco: Se reintenta automáticamente hasta 3 veces con backoff exponencial
  • Fraude Detectado: Se bloquea la transacción y se notifica al equipo de seguridad
  • Card Declined: Se muestra mensaje genérico (por seguridad) sin revelar detalles

📝 Explicación del Sistema de Tracking

  1. Solicitud de Tracking: El cliente accede al link de tracking desde su email, SMS o app. Ingresa el número de pedido o se autentica para ver sus pedidos activos. El sistema verifica que el pedido exista y esté en estado de delivery.
  2. Conexión WebSocket: Se establece una conexión WebSocket persistente entre el cliente y el servidor de tracking. Esto permite recibir actualizaciones en tiempo real sin necesidad de recargar la página o hacer polling constante. La conexión mantiene un heartbeat cada 30 segundos para verificar que esté activa.
  3. Envío de Ubicación GPS: La app del repartidor envía automáticamente su ubicación GPS cada 10 segundos o cuando se mueve más de 50 metros. Incluye latitud, longitud, timestamp, velocidad y dirección (brújula). Los datos se envían encriptados vía HTTPS al servidor.
  4. Cálculo de Ruta: El servidor consulta la API de mapas (Google Maps, Mapbox) para calcular la ruta óptima desde la ubicación actual del repartidor hasta el domicilio del cliente. Considera el tráfico en tiempo real, obras en la vía, y preferencias (evitar autopistas, etc.).
  5. Cálculo de ETA: Con la distancia y el tráfico actual, se calcula el Tiempo Estimado de Arribo (ETA). Se ajusta dinámicamente considerando: clima (lluvia = más lento), hora pico, historial de tiempos del repartidor, y eventos en la zona. El ETA se actualiza cada vez que cambia significativamente (>2 minutos).
  6. Broadcast en Tiempo Real: El servidor envía la ubicación actualizada, la ruta en el mapa, y el ETA a todos los clientes suscritos a ese pedido (puede ser el cliente y también el restaurante). Se usa WebSocket para push inmediato. La actualización es suave (animated) en el mapa.
  7. Notificaciones Push: Se envían notificaciones automáticas en hitos clave: cuando el repartidor retiró el pedido, cuando está en camino, cuando está cerca (< 500m), y cuando llegó al destino. El cliente puede contactar al repartidor por chat o teléfono desde la app.
🌟 Características Avanzadas:
  • Geofencing: Alertas automáticas cuando el repartidor entra/sale de zonas definidas
  • Offline Mode: Si el repartidor pierde señal, se guarda la ubicación y se sincroniza al reconectar
  • Privacy: El cliente solo ve la ubicación durante el delivery activo, no antes ni después
  • Batería: Optimización del GPS para no consumir batería excesiva del repartidor
